01

AI Agent 원리

약 15분

설명 핵심 — Kobi는 대화형 LLM에 “로직을 직접 실행하는 손발(tool)”을 달아준 것입니다. 질문에 답만 하는 것이 아니라, 필요하면 실제로 파일을 읽고 코드를 고치고 명령을 실행합니다.

시대질의 방식응답 방식
인터넷 · DBMS 초창기구조화된 쿼리(SQL 등)로만 이해정해진 형식의 결과값만 리턴
LLM 등장 이후자연어 질의로 이해자연어 문장으로 응답
현재 ChatGPT 웹사이트자연어 질의자연어 응답만 (로컬 파일·시스템을 직접 건드리지 않음)
Kobi (AI Agent)자연어 질의 + 사용 가능한 로컬 tool 목록을 함께 전달“tool 실행 요청” 또는 “문장 답변” 중 하나로 응답

ChatGPT 웹사이트와 Kobi의 차이는 단 하나입니다. Kobi는 요청(request)에 “내 PC에서 실행할 수 있는 tool 목록”도 함께 보낸다는 점입니다. 모델은 그 목록 중에서 필요한 tool을 골라 “이걸 실행해줘”라고 응답할 수 있습니다.

Kobi의 Tool-Calling 루프

flowchart TD
    A[개발자 질문 / 요청] --> B["Kobi 클라이언트
system prompt + 대화 히스토리 + tool 목록 구성"]
    B --> C[Qwen3-Coder-Next API 서버 호출]
    C -->|tool 필요| D[tool 실행 요청 응답]
    C -->|tool 불필요| E[자연어 답변 응답]
    D --> F{사용자 승인?}
    F -->|승인| G["로컬 tool 실행
Read / Edit / Bash 등"]
    F -->|거부| I[실행 취소, 대안 안내]
    G --> H[실행 결과를 대화 히스토리에 추가]
    H --> B
    E --> J[개발자에게 답변 표시]

핵심은 최종 답이 나올 때까지 이 루프가 반복된다는 것입니다. tool 실행 결과가 다음 응답을 결정하고, 더 이상 tool이 필요 없어지면 최종 자연어 답변을 만듭니다.

IT 관점 — 실제 request / response 구조

Kobi(Qwen Code CLI) ↔ 사내 API 서버 Qwen3-Coder-Next-FP8 · OpenAI 호환 endpoint (settings.json의 baseUrl)

→ Request

  • system prompt — QWEN.md 지침 (한국어 응답, 승인 절차, 보안 규칙 등)
  • user prompt — 개발자의 질문 / 요청
  • 대화 history — 이전 turn들 (이전 tool 실행 결과 포함)
  • tool 목록 — Read / Edit / Bash 및 각 스킬의 tool을 JSON schema로 정의

← Response

  • (a) tool 실행 요청 — tool 이름 + 인자(예: Edit, 파일 경로, 변경 내용)
  • (b) 최종 자연어 답변 — 더 이상 tool이 필요 없을 때
  • 둘 중 하나만 응답으로 돌아옵니다
request.json (요약)
// Kobi → Qwen3-Coder-Next API
{
  "model": "Qwen3-Coder-Next-FP8",
  "messages": [
    { "role": "system", "content": "QWEN.md 지침문 …" },
    { "role": "user",   "content": "OrderController를 Spring MVC로 바꿔줘" }
  ],
  "tools": [ { "name": "Read" }, { "name": "Edit" }, { "name": "Bash" } ]
}

이 원리가 보안 정책과 연결되는 이유. tool 실행 요청이 왔다고 곧바로 실행되지 않습니다 — 사용자 승인(approval)이 반드시 필요합니다. 승인을 거치더라도 .env·인증서 파일, git push / rm / del 같은 위험 명령은 settings.json의 permissions.deny로 원천 차단되어 이중 안전장치가 적용됩니다.

02

Kobi 설치 · CLI 버전

약 10분

Kobi는 별도 GUI 설치 마법사가 없는 완전한 CLI/터미널 도구입니다. 설치도 실행도 전부 PowerShell에서 이루어집니다.

Windows 10 / 11 64-bit 일반 사용자 권한 (관리자 불필요) PowerShell v5.1+
1

설치 파일 압축 해제

배포받은 Kobi_Installer_v<버전>.zip을 원하는 로컬 경로(예: C:\Temp)에 압축 해제합니다.

2

Install-Kobi.cmd 실행

압축 해제된 폴더에서 Install-Kobi.cmd를 더블클릭합니다. PowerShell 창이 열리고 진행 로그가 표시됩니다.

3

3단계 자동 배포

기존 프로세스 종료 → ~/.qwen/에 지침·스킬·Computer Use 드라이버 배포 → 환경변수 Path에 실행 경로 등록이 순서대로 진행됩니다.

4

버전 검증 & 완료

kobi --version이 자동 실행되어 정상 동작을 확인하고, 아무 키나 누르면 설치 창이 닫힙니다.

참고. Install-Kobi.ps1은 사내 정책상 허용된 Windows 사용자 계정 목록(allow-list)을 검사한 뒤에만 설치를 진행합니다. 목록에 없는 계정이면 설치가 차단되고 안내 문구가 출력됩니다.

삭제가 필요할 때는 압축 해제한 폴더의 Uninstall-Kobi.cmd를 실행하면 Path 등록과 ~/.qwen 폴더가 함께 정리됩니다 (레지스트리·시스템 전역 변경 없음).

Step 3 · 코드 변경 (Before / After)

BEFORE · 레거시 프레임워크
OrderController.java
public class OrderController extends BaseAction {

    private final OrderService orderService = new OrderService();

    @Override
    public ActionForward execute(
        HttpServletRequest req, HttpServletResponse res) {
        String orderId = req.getParameter("orderId");
        Order order = orderService.getOrder(orderId);
        req.setAttribute("order", order);
        return new ActionForward("orderView");
    }
}
AFTER · Spring MVC
OrderController.java
@Controller
@RequestMapping("/order")
public class OrderController {

    private final OrderService orderService;

    public OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    @GetMapping("/{orderId}")
    public String getOrder(
        @PathVariable String orderId, Model model) {
        model.addAttribute("order", orderService.getOrder(orderId));
        return "orderView";
    }
}
